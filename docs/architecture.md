# 轻量工具箱与 Agent 架构

## 当前结构

站点保持原生 JavaScript 和静态部署。工具页面、Agent 会话与模型适配器分层，避免为本地计算引入常驻服务。

```text
工具目录 ToolCatalog → 分类 / 搜索 / 收藏 / 工作台
                         ↓
                   路由与按需加载
                         ↓
                 工具页面 / 本地计算

AI 界面 → AgentSession → 模型适配器 → 配置的模型接口
              ↓
      动作注册表与参数校验
              ↓
      顺序执行 / 页面操作 / 本地计算
```

`public/tool-catalog.js` 统一工具 ID、分类、工作台关系、处理方式和文件输入标识。首页与侧栏展示工作台入口；搜索、旧链接和收藏仍可到达子工具。工作台统一导航；图片压缩、WebP、Base64 另通过 ImageSession 显式复用 File 引用，其余工具仍拥有独立输入。

加载器按脚本路径保存 Promise，合并预加载与导航同时发生的加载请求。加载失败可重试，已加载脚本不会在当前页面会话中重新执行。工具打开时才注册清理钩子，预加载不能覆盖当前页面的清理逻辑；离开工具时调用钩子释放页面资源。长期演进可迁移为 ES modules，但不能通过删除 script 标签来模拟 JavaScript 内存卸载。

AgentSession 每次请求建立独立运行上下文与 AbortController，防止已取消任务的迟到结果写入新任务。模型返回的动作按顺序执行；入参先通过内置工具所用的 schema 子集校验，执行有超时与迭代上限。动作可通过第二个参数的 `signal` 配合中止。取消时清理不完整的 assistant/tool 历史配对，但不撤销已经发生的副作用。

SVG 预览以图片方式展示，避免将用户提供的 SVG 直接插入页面 DOM。图片处理工具拥有独立状态、文件输入和资源清理逻辑。

## 本地工作流

`ToolCompute` 为 Base64、命名风格和行清洗提供页面/Agent 共享函数。`AgentWorkflow` 允许已校准的本地动作按序组合，通过 `$ref` 传递有类型的步骤结果，不再由模型重新输入中间数据。计划在执行前检查动作白名单、重复 ID、引用方向和参数结构；执行时校验引用解析后的参数，失败/取消即停止。UI 复用结果卡片与进度事件，本地斜杠命令也通过 AgentSession 的同一执行边界。具体接口、限额和模板见[工作流文档](agent-workflows.md)。

## 下一步优先级

| 优先级 | 改进 | 完成标准 |
| --- | --- | --- |
| P1 | 扩展文件复用 | 压缩、WebP、Base64 已支持 File 引用与结果暂存；后续扩展到 EXIF/二维码，并设计 Agent 可用的文件引用，不把 Base64 塞入模型上下文 |
| P1 | 统一可执行能力定义 | Base64、命名风格、行处理已共享；继续迁移图片/格式转换等。目录、参数 schema、运行位置和副作用说明仍需逐步统一 |
| P2 | 深化可执行能力筛选 | 已按 runner 与手动标记区分 automatic/manual/file-input，并移除猜测 DOM 的通用填值；后续统一到可执行能力定义 |
| P1 | 密钥生命周期 | 默认会话保存，持久保存由用户选择；公共服务密钥放独立代理，并配鉴权、额度与速率限制 |
| P1 | 校准已有工具正确性 | 单独验证时区源区域转换、格式转换边界、网络错误等，不能以导航回归代替算法正确性测试 |
| P2 | 按任务发现能力 | 已优先最新搜索发现的 schema（最多 20 个），后续减少静态大提示词和无关历史 |
| P2 | 副作用分级 | 本地纯计算、页面修改、联网分别描述；独立纯计算可并发，有依赖或副作用的操作按序执行 |
| P2 | 结果与预算控制 | 已限制单次结果、动作数和工作流步数，展示步骤及错误；仍需历史 token 预算、大结果引用和安全重试 |
| P2 | 性能隔离 | 图片批处理及大文本使用 Worker，设置像素/内存/并发预算，支持逐项取消 |

图片压缩和转换适合共享文件工作台，但哈希与 HMAC 应保留不同操作语义；二维码生成和识别也应保留方向。HTTP 请求测试、cURL 生成、状态码查询适合共享请求信息，不能混成一个自动发起网络请求的按钮。数据格式转换可逐步共享解析器，JSON 对比与文本对比则应保留不同的比较逻辑。

GitHub Pages 继续承载静态前端；只有需要隐藏密钥、统一鉴权或跨域代理时才增加独立后端。当前不需要为了这些改进引入多 Agent 服务、数据库或完整任务编排平台。

## 验证边界

单元测试覆盖 Agent 取消、旧响应隔离、顺序依赖、参数校验、超时和迭代限制；浏览器回归覆盖图片流程、分类/工作台、旧入口/收藏、脚本重复加载和 SVG 隔离。浏览器测试屏蔽外部 HTTPS 请求，不代表真实模型或第三方服务已完成联调，也未覆盖全部工具的算法正确性。

## 依赖维护

开发服务使用 Node.js 自带 `--watch`，移除 nodemon 及其监听依赖。`qs` 使用 override 升级到已修复版本，因为 Express 4 的依赖范围仍限制在旧的小版本；升级 Express 后应重新检查是否还需要该 override。依赖更新后运行 `npm audit` 和浏览器回归，审计结果只反映当时已公布的通告。

## 发布和客户端更新

构建为 HTML 注入内容版本，所有应用脚本/样式 URL 携带版本参数，生成 `version.json` 及 Worker 内的 SHA-256 资源清单。Worker 安装新版本时，先按路径在本 scope 保留的旧版本缓存中由新到旧查找，重新计算 SHA-256 与新清单一致才复制，否则带新版本参数从网络下载并校验；路径只用于定位候选，内容损坏或被篡改的副本不会进入新版本。最多并发处理八个资源，全部校验通过后才完成安装；任一文件失败即删除新缓存、停止其余处理并保留当前版本。用户确认更新后发送 ACTIVATE，只有发起操作的标签页刷新；旧标签页按旧版本参数读取保留缓存，超出最近三个版本的资源返回失败，避免混用新脚本。

缓存前缀包含 scope 路径，不清理同域其他项目。version.json 不经过 Worker 缓存，检查使用 no-store 与查询参数；Worker 注册使用 updateViaCache:none。GitHub/CDN 仍可能有传播延迟，更新失败保留现有运行版本。GitHub 工作流使用 configure-pages/upload-pages-artifact/deploy-pages，仓库 Source 需设为 GitHub Actions。

ImageSession 只保留最近一组 File 引用，最多 20 个、共 100 MiB，提供清除和结果暂存。切换页面清理各工具的对象 URL 与订阅，刷新则整个会话消失。元数据接口仅返回名称/类型/大小，不把文件内容发送给模型。文件选择、格式验证和计算仍在具体工具中完成。

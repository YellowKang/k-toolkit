## 复现后修复

1. Responses 非流式请求收到 SSE 时，原先按 JSON 读取而报连接失败。现在根据 Content-Type 处理，流中错误和缺失结束事件明确报错。
2. Chat 工具历史切到 Responses 时，工具调用原先嵌在消息正文内。现在转成顶层调用/结果，保留 `call_id`，使用无服务器存储的完整历史；同模型、同端点保留 Responses 推理与输出项，切换模型使用通用历史。
3. 无可用通道原先显示成参数错误。现在有固定的模型路由提示，并支持从接口获取模型、手动选择和测试；错误正文不回显。
4. 工作流原先只返回最后一步，Agent 为展示中间 JSON 又运行一次。新增 `returnSteps` 后，实测同一请求只执行一次三步工作流，返回中间 JSON 与最终哈希。

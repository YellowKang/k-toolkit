# 工作流运行记录与失败恢复

## 页面使用

在「我的流程」编辑步骤与输入后，点击「预览计划」查看动作顺序、依赖、参数摘要及输出字段。预览不执行计算；敏感参数按字段名遮盖，长文本摘要截断。输入或步骤改变后会标记预览过期，点击运行时重新校验并使用独立快照。

失败或取消后，「继续本次运行」会说明可复用的步骤数量及接续位置。可以修改尚未完成的步骤；修改已经完成的步骤、其参数或原始输入，会禁止恢复并要求重新运行。恢复不会再次执行已提交的前缀，即使前缀包含随机生成等动作，也复用原来的真实结果。

「运行记录」显示运行 ID、来源、状态、步骤耗时与尝试次数。支持刷新、摘要导出和清除；正在运行的记录受到保护。当前标签页还持有恢复数据时，可把手动任务载入编辑器，作为固定输入预览、修改和恢复。固定文本可以直接编辑。助手来源的任务在助手中恢复，避免把手动输入混入模型可访问的执行记录。

## 保存范围

- 本机持久保存最多 30 条运行摘要，最多 512 KiB。摘要只有流程名称、动作、状态、时间、尝试次数等元数据，不包含任务输入、中间结果、密钥或原始错误正文。
- 真实恢复检查点仅在当前标签页内存，最多 10 条 / 4 × 1,024 × 1,024 个序列化字符；按最近使用保留。刷新、关闭标签页或被淘汰后，旧摘要依然可以查看，但无法直接恢复。
- 流程编辑草稿仍按既有规则保存，其中包含本次输入。清除运行记录不会清除编辑草稿、保存的模板或已经展示的独立结果；这些内容有各自的清除入口。
- 固定文本属于模板参数。将恢复数据载入编辑器后保存为流程，会一并保存其中的固定文本；使用「原始输入」占位符的模板不会保存当次输入。
- 保存摘要失败时，计算仍可完成，界面明确提示未保存。当前结果和内存检查点仍可使用。
- 运行摘要纳入数据备份的「工具数据」分组，合并按 ID 去重；恢复检查点不会随备份导出或导入。导出的运行摘要不具有执行权限。

## 执行边界

每条流程仍为 1–12 步，只允许白名单中的本地计算，不支持网络、文件池、页面修改或递归工作流。步骤入参及结果、最终合并结果沿用 65,536 字符限制。每个标签页最多同时执行 4 个流程，同一个运行不能同时恢复；每个运行最多 20 次尝试。

每步最多等待 15 秒；取消或超时会向动作发送 AbortSignal，及时结束等待，并禁止迟到结果提交。Worker 等协作式动作会释放实际资源；同步 JavaScript 计算仍需依靠已有输入/复杂度上限，计时器不能抢占主线程。

恢复会校验完整计划、不可变前缀、已完成动作的函数和参数契约，以及应用版本。检查点从未从持久摘要反序列化；外部导入的记录不能伪造已完成结果。

浏览器 Web Locks 保护摘要更新与运行活跃状态。跨标签页读取时，没有活跃运行锁的旧 running 记录显示为 interrupted。清理记录保留正在运行的项；备份写入与摘要写入使用同一锁。

## Agent 接口

- `preview_workflow({steps, returnSteps?})`：返回可展示的计划，不执行动作。
- `run_workflow` / `run_workflow_template`：原结果契约保留，增加 `runId`、`resumable`、`historySaved`，存储失败时附 `historyWarning`。
- `list_workflow_runs({})`：返回最近助手来源的摘要及本标签页是否能恢复，不返回输入、结果或手动任务。
- `resume_workflow({runId, steps?, returnSteps?})`：不传 steps 时使用原计划；提供 steps 时检查已完成前缀不变，再执行尚未完成部分。仅能恢复助手来源任务。

`AgentWorkflow.checkpoint` 是本页 UI 的内部接口，不注册为模型工具。

## 验证

`npm test` 覆盖不执行的预览、秘密字段遮盖、前缀复用及修改拒绝、取消/超时和迟到结果、并发恢复、契约变更、来源隔离、刷新、配额失败、跨标签存储、检查点淘汰和备份校验。

`TEST_BUILD=1 npm run test:browser -- workflow-resume` 验证真实页面上的预览→失败→修正→恢复、固定输入载入、摘要导出、刷新和跨标签运行锁、存储失败、双语与 375/768 布局；可加 `TEST_BROWSER=firefox` 或 `TEST_BROWSER=webkit`。

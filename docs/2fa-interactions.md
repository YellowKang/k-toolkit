# 2FA 分组、搜索与验证码时效

2026-10-27。

## 账号分类与检索

导入后的账号按发行方分组，忽略大小写与多余空白，组内按账号名称排序。没有发行方的账号放入「未分类」，可通过卡片的「编辑」补齐。邮箱域名不用于推断发行方；分组不会修改或合并账号。

分类下拉与关键词搜索可同时使用；多个空格分隔的关键词取交集，搜索发行方、账号和备注，不搜索密钥。页面显示命中数与总数，支持清除筛选和折叠分组。编辑、删除或再次导入后立即更新分组；折叠组不计算隐藏卡片的验证码。分组和搜索状态仅在解锁页面内存中，原有加密存储格式保持兼容。

## 旧码复制修复

此前快速计算读取按钮上的验证码，看板读取缓存码。当后台计时器延迟而时间步已变化时，复制仍会取得旧码。以公开测试密钥模拟时间前进 90 秒、暂停周期刷新，修复前的浏览器回归能稳定失败。

现在点击复制时重新计算当前验证码；计算期间若跨过时间步会重算。支持时通过 ClipboardItem 的 Promise 在点击事件内启动剪贴板写入，保持用户激活；其他浏览器使用文本复制。剪贴板只有纯数字。验证码按钮不再使用会延时恢复旧文字的通用复制动画。页面回到前台立即刷新，快速计算的异步结果只允许更新对应的当前输入。

以相同密钥和 10 个固定时间点，在本地对照参考网站使用的 [OTPAuth 9.4.0](https://2fa.uihtm.com/assets/js/otpauth.umd.min.js)，基础 TOTP 结果一致。比较没有把密钥提交到第三方页面。此次确认并修复了缓存时效问题，没有使用真实账户执行登录验证，不能据此追溯此前某次登录失败的唯一原因。

## 验证

- RFC 4226 / 6238 原有测试保持通过，新增纯函数测试覆盖分组、组合搜索、未分类及不搜索密钥。
- `npm run test:totp` 包含加密看板全流程和新增 `totp-state-browser.cjs`：覆盖旧码复制、前台恢复、异步输入竞争、分类、搜索、编辑重分组、锁定、XSS 字符串、移动端和英文。
- Chromium 和 Firefox 的 2FA 专项测试通过；使用 37 个合成账号检查桌面和 390px 布局，原生 Chromium 剪贴板验证为纯数字且与显示值一致。
- 最终构建版的 Chromium / Firefox 全量浏览器回归与 153 项单元测试全部通过，包含加密备份、92 工具 XSS/双语检查、缓存更新以及已有 Agent / 会话 / 工作流能力。
- 测试仅使用公开测试密钥和合成账号，截图中的实际账号及用户密钥均未写入代码或测试夹具。
